## 🤖 2. AI 개발 지침 및 설계 구조

### 🎯 목적
* AI 에이전트가 코드를 작성, 리팩토링, 디버깅할 때 가짜 데이터 가정 및 하드코딩 상수로 인한 연쇄 장애를 방지하고, 리소스 누수와 타임아웃을 안전하게 제어하는 아키텍처 가이드를 제공합니다.

### 📦 패키지 및 타깃 클래스 경로 구조
```plaintext
backend/
├── llm/
│   ├── client.py              # Ollama API HTTP 통신 및 타임아웃/텔레메트리 설정 제어
│   └── rag_engine.py          # Chroma DB 연동 및 동적 메타데이터 검증 로직
└── database/
    ├── sqlite_logs.py         # SQLite connection 컨텍스트 매니저 기반 자원 반납 가드
    └── stats_db.py            # 동적 스키마 검증 및 KST 타임스탬프 기반 날짜 쿼리 바인딩
```

### 🛠️ 개발 단계 (Step-by-Step 상세 로직)

#### 1단계: 데이터 스키마 및 메타데이터 동적 검증 (Dynamic Schema Check)
* DB 적재 및 필터링 시, 하드코딩된 상수 카테고리에 의존하지 않습니다.
* 쿼리 또는 연산 전에 `SELECT DISTINCT event_type, source_tool FROM ide_activity_logs`와 같은 조회를 수행하거나 입력 데이터를 동적으로 파싱하여 DB에 존재하는 실제 도구 및 이벤트 타입을 기반으로 처리합니다.

#### 2단계: KST 타임스탬프 명시적 주입 및 타임존 격리 (KST Time Binding)
* 로컬/컨테이너 시간대 설정에 영향받지 않도록 `timezone(timedelta(hours=9))`를 명시적으로 사용하여 Python 애플리케이션 레벨에서 KST 시간을 계산합니다.
* SQLite `BETWEEN` 연산 시 `YYYY-MM-DD 00:00:00` 및 `YYYY-MM-DD 23:59:59` 포맷의 시/분/초를 채운 풀 타임스탬프 문자열 매개변수를 생성하여 바인딩 주입합니다.

#### 3단계: Context Manager 기반 커넥션 누수 방지 (Double Resource Guard)
* 모든 데이터베이스 연산은 `with get_connection() as conn:` 문을 사용하여 예외나 `return` 문에 의해 조기 탈출하더라도 항상 자원이 해제되도록 보장합니다.
* 컨텍스트 매니저 사용이 어려운 예외적 경우 `try-finally` 블록의 `finally` 절에 `conn.close()`를 기계적으로 배치합니다.

#### 4단계: HTTP 클라이언트 타임아웃 튜닝 (High-Latency Timeout)
* Ollama 추론 및 Chroma DB 적재 등 대량 청크 작업용 HTTP 클라이언트(httpx, requests 등) 초기화 시 `timeout=180.0` 또는 `timeout=None`을 지정하여 대기 시간이 수십 초 이상 걸리더라도 통신이 단절되지 않게 설계합니다.

#### 5단계: 정규식 대상 전처리 문자열 교차 검증 (Sanitized Regex Matching)
* 자연어 날짜 파서 등에서 공백 제거(`replace(" ", "")`)나 정제 과정을 거친 문자열 변수를 정규식 매칭 함수(`re.search`, `re.match` 등)의 대상 인자로 정확히 넘겨주었는지 검증합니다.
* 문자열 분할 및 슬라이싱 시 범위를 벗어나는 인덱스 참조가 없도록 길이 검증(`len()`) 및 구조적 존재 가드를 이중으로 배치합니다.

#### 6단계: 원격 Telemetry 차단 환경 변수 주입 (No-Telemetry)
* Chroma DB 엔진 등의 원격 통계 비활성화를 위해 애플리케이션 구동 진입점(`main.py` 또는 환경설정 로드 시점) 및 Docker 환경 구성에 `ANONYMOUS_TELEMETRY=False`를 강제로 로드하도록 설정합니다.

## 🚨 3. 철벽 코드 컨벤션 및 제약 조건
* **[300줄 분리 규칙]**: 본 가이드라인을 구현하는 개별 소스 코드 파일은 단일 파일 기준 **300줄**을 초과할 수 없습니다. 300줄에 임박하면 기능을 별도 모듈이나 utils 파일로 신속하게 분리하십시오.
* **[지시 이행자(Typist) 모드]**: 에이전트는 기획서에 명시된 기능 범위와 명세서의 지침에만 한정하여 코드를 구현하며 임의의 아키텍처 확장 및 뇌피셜(Hallucination) 코드 생성을 원천 금지합니다.
* **[응답 사설 및 설명 배제]**: 에이전트 수정 결과 출력 시 요약, 설명, 사용법 등의 텍스트 낭비를 금지하고 수정 대상 파일명과 정확한 코드 블록만 간결하게 제공합니다.

## 🧪 4. 필수 테스트 케이스 및 검증 시나리오

### 1) 메타데이터 동적 유효성 검증 테스트
* **시나리오**: DB에 기존 카테고리 외 신규 도구(예: `Cursor`, `VSCode`) 및 신규 로그 레벨(예: `LOG_DUMP`)이 적재되었을 때, 하드코딩되지 않은 집계 함수가 이를 누락 없이 신규 카테고리로 자동 인식하여 집계 통계 결과에 정상 반영하는지 확인합니다.

### 2) KST 타임스탬프 날짜 경계값 테스트
* **시나리오**: 로컬 컴퓨터 시계가 UTC 상태일 때, KST(`UTC+9`) 기준의 날짜 및 시/분/초 풀 타임스탬프(`2026-06-22 00:00:00` ~ `2026-06-22 23:59:59`) 검색 시 KST 범위 내의 데이터만 누수 없이 SQLite 및 Chroma DB 쿼리로 올바르게 탐색되는지 검증합니다.

### 3) 커넥션 잠금(Lock) 및 누수(Leak) 스트레스 테스트
* **시나리오**: 100회 이상의 중복 로그 유입 및 강제 예외 발생 분기(Early Return)를 연속 호출한 후에도 DB 커넥션이 정상 반납되어 `database is locked` 데드락 에러 없이 정상적으로 신규 쓰기/읽기 동작이 수행되는지 테스트합니다.

### 4) 정규식 전처리 변수 무결성 테스트
* **시나리오**: 질문 원본에 공백 및 특수문자가 섞여 있을 때, 정제된 문자열 변수가 날짜 파서 및 정규식 분석 대상에 일관되게 주입되어 분기 파싱에 실패하지 않고 기본값으로 탈락하지 않는지 교차 검증합니다.
